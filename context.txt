## SHOPIFY CHECKOUT FLOW (Advanced GraphQL)
1. GET /cart.js — session init, cookies
2. GET /products.json — find cheapest product
3. POST /cart/add.js — add to cart
4. POST /cart — start checkout (get checkout URL + ID)
5. GET checkout URL — extract sessionToken, signature, stableId, queueToken
6. POST checkout.pci.shopifyinc.com/sessions — vault card (get vault_id)
7. POST /checkouts/unstable/graphql — SubmitForCompletion mutation
8. Poll for receipt (separate 120s session) — CHARGED/LIVE_3DS/LIVE/DEAD

## PROXY VALIDATION (Shopify-based, 30 workers)
- Proxies tested against REAL Shopify stores (not httpbin)
- Stores: madebycleo, allbirds, kith, gymshark, colourpop, bombas, tesla, buckmason
- Each proxy tested against up to 3 stores (retry on different)
- 30 concurrent workers (asyncio.Semaphore(30))
- Proxy is LIVE: HTTP 200 with product JSON, or 301/302 redirect
- Proxy is DEAD: timeout, DNS fail, connection refused, non-Shopify response
- Shared aiohttp session for all validations
- Only live proxies added to DB, dead discarded

## ERROR HANDLING (God-level)
- 30+ exception types classified (CRITICAL/ERROR/WARNING/INFO)
- Error deduplication (don't spam same error within 30s)
- Circuit breaker (auto-disable failing features after 5 failures, 60s recovery)
- Admin alerts on CRITICAL errors (dedup'd, 60s cooldown)
- safe_send/safe_edit with 3 retries + NetworkError handling
- retry_async with exponential backoff + jitter + circuit breaker
- db_retry with 5 retries on "database is locked"

- Never crash silently

## ANTI-SPAM
- Command cooldowns: /sh=3s, /st=3s, /chk=30s, /bin=2s, /addproxy=60s
- Hourly limits: FREE=50, BASIC=200, PRO=500, MAX=1000, ULTRA=5000
- Card repeat detection: same card within 5 min = blocked
- Max 1 concurrent mass check per user
- refund_hourly() if check fails
- cancel_mass() if check never starts

## STORE HEALTH SCORING
- 0-100 score per store (persisted to SQLite)

- In-memory cache + batched DB commits (every 5s, not per-check)
